## 一、核心概念区分:ASK 和 sandbox 不是一回事(最该讲清的一点)

很多人(含作者初读时)把"权限"当成一个开关,把 ASK 和 sandbox 当同类。
它们回答**两个不同的问题**:

| | ASK(授权 authorization) | Sandbox(隔离 containment) |
|---|---|---|
| 回答 | **该不该让它跑?** | **它跑起来能碰到什么?** |
| 时机 | 执行**前**——门口保安 | 执行**中**——房间的墙 |
| 放行后 | 命令拿用户**全部权限**在真实系统跑 | 命令即使放行,只能在隔离环境动 |
| 靠什么 | **人**做 yes/no | **操作系统**强制 |

一句话:**ASK 是"门口问要不要放它进来",sandbox 是"就算进来,房间也是
空的、砸不到东西"。** ASK 管授权,sandbox 管后果——授权对 ≠ 后果安全
(用户可能被骗着点 yes,或命令副作用超出预判)。

**推论(sandbox 的存在理由)**:`--auto`/headless/autopilot **没有人**,
ASK 这道"靠人判断"的门自动变成放行(`ASK→ALLOW`),授权层直接塌方。
此时唯一站着的防线是 sandbox 的墙。所以:
> 有人在场 → ASK 够用(人是判断者);无人在场 → ASK 塌方,只有 sandbox
> 兜底。这不是"交互模式特殊豁免",是"有人的地方用人判断,无人的地方
> 用墙"——两种场景配两种防线。

"REPL 为什么不强制 sandbox" 的答案即此:REPL 有人,每条 Bash 都 ASK
弹给人(D44),人就是判断门。

## 二、权限不是开关,是风险梯度(Write 的三档谱系)

作者初始心智模型:"碰 Write = 要 permission"(二元)。代码给的是
**按危险程度分层的谱系**(`tier_based.py` evaluate + `_matches_tier3`):

```
Write(path) 依次过门:
  Tier1 敏感路径(~/.ssh 等硬编码) → DENY   ← 最危险,人都不问,直接禁
  Tier2 用户 deny glob            → DENY
  Tier3 is_read_only?             → 是→放行(读哪都行,读不改变世界)
        path 在 cwd 内?          → 是→ALLOW(你的地盘)
        越界                     → ASK(可疑但可能合理,问一声)
```

**洞察**:"要不要 permission"这个二元问法,被代码替换成"这个操作有多
危险"的连续判断。约束强度匹配副作用大小——读放行、cwd 内写放行、越界
写问、敏感区写禁。**分级门,不是二元门。**

## 三、Write 与 Bash 分道扬镳的物理起点:一个 None

`_extract_path_arg`(tier_based.py:336):Write 有 `path` 字段→抽出;
Bash 只有 `command`(shell 字符串)→返回 `None`。**这个 None 决定 Bash
逃过后面所有路径门**(Tier1/2/3 全靠 path,`path is None` 就跳过)。

| | Write | Bash |
|---|---|---|
| 参数 | `path`(结构化) | `command`(通用 shell 字符串) |
| 系统可见性 | **看得见碰哪个文件** | **看不清副作用**(变量/管道/子进程) |
| 能画牢? | 能(三档同心圆) | 不能(静态解析命令不可靠) |
| 退路 | 天然按 path 授权 | 只剩 ASK(问人)或 sandbox(隔离) |
| 敏感区(~/.ssh) | Write → **DENY** | `cat ~/.ssh` → 最严只 **ASK**(F13 缺口) |

**触目惊心的实证**:同碰 `~/.ssh`,Write 判 DENY(Tier1 硬红线按 path),
Bash `cat ~/.ssh/id_rsa` 只 ASK——因为 Tier1 那道红线**看不见命令字符串
里的路径**。这是 Bash"参数不可见"的直接代价:它连 Write 有的"敏感区
硬禁"都给不了。

## 四、章魂落点(接 brief 的"两类模型说了不算")

- **Write 的安全来自可见性**:参数即 path,精确授权,画牢。
- **Bash 的危险来自不可见**:通用计算通道,静态画牢原理上不可能。
- **D44 做的事**:看不清就把判断交回人(交互每条 Bash ASK);真正的
  OS 级牢只有 sandbox 给(隔离在内核层,不依赖看懂命令)。
- **安全默认值哲学(brief 难题的答案雏形)**:敏感路径硬拦**不可配**
  (最危险的事不靠用户配置兜底),sandbox **opt-in**(有性能/环境成本,
  且 ASK 在有人场景已够)——分界线原则:**不可逆/不可审计的伤害→硬拦;
  可由在场的人判断的→ASK;无人场景的兜底→sandbox**。

## 五、叙事钩子(写作时可用)

用户一句"我让他写文件,不是直接出 Write 吗,为什么还调 Bash?"——
这个天真问题是整章最好的入口:同一个目的两条实现通道(结构化 Write /
通用 Bash),而两条通道的权限机制**在原理上不同**。从这个问题出发,
自然走到"可见性决定可授权性"→"不可见只能问人或隔离"→"无人场景 ASK
塌方所以要 sandbox"的完整链。比任何"权限系统有三层"的平铺都好。
