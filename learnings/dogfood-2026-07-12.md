## 四条发现(飞轮沉降)

### F1 — `/compact` 门槛对显式命令撒谎

- **现象**:两轮重对话后 `/compact` 回 "(nothing to summarize)"。
- **根因**:`full_compact` 的 `len(messages) <= _PRESERVE_RECENT(=12)` 守卫
  ——为自动压缩场景设计的保留窗,把用户显式命令也拦了,且拒绝信息不真
  (有东西,只是不到 12 条)。
- **去处**:backlog——显式 `/compact` 应尊重用户意图(缩小 preserve 窗)
  或如实说明拒绝理由。

### F2 — headless 无法授权 cwd 外路径(或不可发现)

- **现象**:`OPENHARNESS_PERMISSIONS__ALLOW="Write(**)"` 下写 `/tmp/...`
  仍被拒。
- **根因**:文件工具 allow 规则是 **cwd 相对 glob**(rules.py 设计如此),
  `**` 够不到 cwd 外。benchmark 里 workspace=cwd 所以从未暴露。
- **去处**:backlog 三选一——支持绝对路径 specifier / 文档写明边界 /
  维持安全边界但拒绝信息说清"cwd 外不可授权"。

### F3 — 无 `--isolate` 的修复循环把副产品拉进活仓库

- **现象**:练习 5 三连败后,repo 根目录出现无人认领的 `?? fizzbuzz.py`。
- **根因**:模型被 /tmp 拒后**自适应改道**写进 cwd(`Write(**)` 放行),
  但 gate 检查的是 /tmp 路径,照样失败——副产品留在了工作树。
- **双重价值**:①A5"被拒后行为"的活样本(没有原样重试,换了路)——
  P1 eval 开题时沉为 case;②`--isolate` 存在意义的实证。
- **去处**:A5 dataset case 源 + backlog(无隔离修复循环收尾时可提示
  工作树新增 untracked 文件)。

### F4 — 模型编造 OH 的 YAML 权限配置格式

- **现象**:被拒后模型建议在 "harness 配置里" 加 `permissions: allow:`
  YAML 块——OH 没有 YAML 配置,全部走 env/settings。
- **性质**:自信编造宿主系统的配置语法(通用知识污染),与分类学发现三
  同族:原料半真(别的系统确实这么配),装配全错。
- **去处**:错误消息可考虑内嵌正确的解法示例(env 变量形态),让模型
  转述时有真话可抄;未来 A6 错误恢复 eval 的 case 源。

## 教学沉淀(补课两则)

1. **三层"变小"机制**:Layer1 head-tail truncate(单条工具结果,返回
   瞬间)/ 主动压缩 L2-L4(每次请求前,分级)/ reactive drop-oldest-pair
   (PTL 异常后,丢最老一对,≤3 次)。chat 里模型把第一层的策略安到第三
   层头上——原料全真、装配全错的标本,再证"完成门不信自评"。
2. **headless 四栏合同**:目标(prompt)/ 权限(ALLOW env)/ 完成判据
   (--verify | --goal-condition)/ 预算(--max-iter/--max-turns/--timeout),
   回执 = JSON envelope + exit code + journal。headless 全部表面即此四栏。
