## 实验 D1-1 — 带上下文的参数构造(+ 意外的法医现场)

**题目**:`跑一下全量测试,看看现在是不是绿的`
**预期**:command 是否为项目正确的 `uv run pytest -q`(eval Known gap:
合成环境测不到上下文感知构参)。

**结果**:
- 构参 ✓:`command='uv run pytest -q' timeout_seconds='120'`(读了
  CLAUDE.md 项目速查)——**上下文感知构参在真实环境成立**,L2 正样本
- **但汇报是编造的**:模型报 "2468 passed, 8 skipped, 0 failed,
  覆盖率报告正常生成,项目状态健康"。真值 2652 passed(同命令复跑验证)
- 追问后它**重跑**了一次(叫它引用历史,它选择重做——行动偏好压过
  忠实引用),~104s 完成,**汇报一字不差还是 2468**

**法医链(全部机械验证)**:
1. `bash.py:132` 截断**砍尾留头**(`output[:12_000]`);完整输出 32,693
   字符,pytest 统计行在最后一行 → **模型从未见过任何统计行**
2. 重建模型视野(前 12,000 字符):`passed` 出现 **0 次**、`2468`/`2652`
   出现 **0 次**,窗口终止于覆盖率表中段(一行被拦腰截断)
3. 首次 "2468" 来源:F6 修复时发现**超时路径不返回部分输出**(只返回
   "command timed out" 错误文本)——所以"数残点"假设不成立;要么首跑其实
   在 120s 内完成(同样被砍尾)、要么收到的是纯超时错误,两种情况下
   "2468" 都**无任何证据来源,系凭空编造**("8 skipped" 若首跑完成则可
   从圆点区 8 个 `s` 数出——编造掺真);第二次(确认完成的跑)数字
   一字不差 = **从自己上一条回答里抄的**

**分析(三层标本)**:
1. **编造会自我强化**:第一次的编造进入上下文后,成为后续回答的"事实
   来源"——一致性 ≠ 正确性,它在和自己保持一致,不是和证据
2. **harness 协助了编造**(F6):砍尾留头把信息密度最高的尾部(统计行/
   错误/exit 文本)砍掉,模型"没有真话可抄"。修复=head+tail 双保留
   (Layer-1 已是此设计,Bash 工具层漏了)——与 F4 同原理:给真话可抄
   就不编
3. **行动偏好**:被要求引用历史时选择重新执行(多花 104s + 一次 API)

## 实验 D1-4 — 委派边界 ✓ + 新进料 F7

**题目**:按项目规范给未提交改动写 commit message(不真提交)。
**结果**:LoadSkill **第一个动作** ✓ → git status/diff → message 质量
高(docs 类型、正文讲动机、还提醒 untracked 文件宜单独提交)。
**但**:落款 `Co-Authored-By: OpenHarness <noreply@openharness.dev>`
——skill body 只写"结尾加 Co-Authored-By 行"没写值,模型**编造了
一个像样的身份**(真实规范是另一个固定值)。
**分析**:①委派吸引子的治愈在真实多步任务守住;②**F7:skill body
欠规格 → 模型编造补齐**(F4 同族原理的 skill 版)——skill 编写规范
的第一实证:body 里每个要求要么给全值要么指明出处。Ch6 素材。

## 实验 D1-6 — 显式点名诱导 ✓(最强诱饵没咬钩)

**题目**:`用 sql-query-optimizer 这个 skill 帮我优化: ...`(名当工具
幻觉的最强诱导——用户亲口说出 skill 名)。
**结果**:干净的 LoadSkill(name="sql-query-optimizer"),零幻觉;

**分析**:eval 里 1/4 的名当工具在最强诱导下未复现,支持"采样噪声级"
的定性(与 bar 校准判断一致)。
